# 舱单数据定义

id是主单、分组单或箱货明细唯一字符串编号，parent为空表示主单。节点申报件数、净重和毛重是其完整子树的申报总量，校验时只加直接子节点，避免多层重复计数。包装 carton=1件；pallet 与历史托/卷/捆按口径换算（见下）。重量kg与t统一为kg。件数必须非负整数，净重非负且毛重不得低于净重。
拆并结构采用每节点最多一个父级的有向图；自环、长环、缺父级均阻断封存，保留环路径。不会以平面求和替代逐层校验。
危险品按明确分类与UN编号检查，3类与5.1类禁止同箱；未知分类和缺失编号需复核。此演示规则只覆盖文中三类，不替代运输合规审批。
报关总量只汇总**对平且裁决成立的主单**，与context.json内的申报件数、净重和毛重逐项比较。未对平/口径未裁决主单进入 `excluded_roots` 并附原因码，不进入汇总。重复同值折叠，重复编号冲突全部隔离。原始计数=采纳+隔离+空行+重复表头+重复同值行。
封存需所有图、重量、危险品、采信问题处理完毕，且没有被排除的主单。数值均Decimal，对外字符串保留精度，编号不转整数。

## 单据日期与新旧两套包装口径

CSV 末列 `doc_date`（YYYY-MM-DD）为单据日期；`context.json` 中 `effective_date` 是新口径生效日，`received_at` 是当前接收批次日期。

| 口径 | 生效区间 | 包装换算（件/单位） | 不支持的单位 |
|---|---|---|---|
| old 旧口径 | 单据日期 < effective_date | carton=1, pallet=10, 箱=1, 托=10, roll=1, bundle=2 | — |
| new 新口径 | 单据日期 ≥ effective_date | carton=1, pallet=12, 箱=1 | 托 / roll / bundle（记 NONSTANDARD_UNIT，保留原值不按0求和） |

- 每行同时保留 `caliber_results.old` 与 `caliber_results.new` 两套件数/净重/毛重，原始 packages/net/gross 永不改写。
- `cross_period=true` 表示单据日期与接收日期跨生效档。同档行直接采用单据日期对应口径。
- 跨档提单按整树裁决：先看单据日期旧口径能否让原值与逐层申报对平（可解释则沿用旧口径）；旧口径解释不了再看接收日期新口径能否对平（可解释则改用新口径）；两套都解释不了记 `CALIBER_UNRESOLVED`，该提单排除出申报汇总。不可换算只代表该口径不适用，不等同于差异无法解释。
- 裁决采用值写回 `pieces/net_kg/gross_kg` 驱动逐层重量核对；双口径明细留在 `weight_checks_by_caliber` 供复核。
- `POST /api/runs/{id}/caliber` 支持 `auto`（逐提单裁决）与 `force_new`（接收批次统一新口径）。已复核批次返回 409 CALIBER_LOCKED；force_new 任一提单无法按新口径解释时返回 422 CALIBER_SWITCH_FAILED，候选结果不落库，原批次结果与原值完整保留（回滚）。
- 同输入+上下文+规则版本生成相同批号；重跑/重复切换不产生第二条批次、不重复累计差异。口径策略参与摘要，auto 与 force_new 是不同批号；输入快照字节不变。
